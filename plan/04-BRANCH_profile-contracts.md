# Feature: profile mechanism — lot 0 contracts and parity corpus (Python side)

## Objective
Deliver the Python library's share of lot 0 of the `profile-mechanism/1` design (conductor `DESIGN.md` R3.1, SHA-256 `020270f6…`, §14.2), so that `bpmn_io.profile` (target 0.3.0) can later be implemented against frozen contracts and independently authored expectations. The lot produces **no interpreter**: no loader, compiler, evaluator, lint bridge or CLI code (§14.2, lot 0 gate). It produces pinned contract artifacts, the Python binding of each contract, and corpus cases whose expected outputs are checked by independent Node references (Ajv 2020, an RFC 8785 reference canonicalizer, Node `crypto`) before any Python implementation exists.

## Inputs (authority)
- Design: `DESIGN.md` in the conductor design folder (local, read-only; path given at launch) **R3.1** (exact SHA-256 recorded in Lot 19) and its companions in the same folder; lot-0 errata in `CONVERGENCE-R3.md`; owner ratification of §16 (all 11 defaults) in the conductor's owner-decision record (2026-10-14).
- Python consensus: `CONSENSUS-R3-bpmn-py.md` (M1 validation strategy, m1–m5) in the same folder.
- Library baseline: published `bpmn-io` 0.2.1 (`main`), literal bpmnlint 11.15.0 port under `src/bpmn_io/lint/`.

## Scope / Guardrails
- Library scope only: no business or private-repository name, constant or private fixture enters this repository. Every vendored artifact is synthetic/neutral; a grep guard proves it (Lot 19).
- The conductor repository is read-only for this branch. Vendoring copies bytes and pins them by SHA-256; nothing is written back to the conductor repository. Findings for the design go to the conductor, not into DESIGN.md.
- Expected outputs are authored from the DESIGN text, then checked against the independent Node references. They are never generated by Python code from this repository, and never rewritten to match an implementation.
- Node is used only in `tests/oracle` (already the differential oracle). Pins exact versions.
- Same repository rules as previous plans: English text, local gate before every commit, one logical change per commit, explicit `git add`, **no attribution trailers of any kind** in commit messages.
